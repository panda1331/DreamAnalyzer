# Чек-лист функциональных проверок (API / Backend)

## 1. Модуль «Аутентификация и авторизация» (FR-01 — FR-05)

### FR-01, FR-03: Регистрация и хеширование
* [ ] (+) Успешная регистрация с валидными уникальными данными (username, email, password).
* [ ] (-) Регистрация с пустым username / email / password (ожидаем 400 Bad Request).
* [ ] (-) Регистрация с невалидным форматом email (ожидаем 400).
* [ ] (-) Регистрация с паролем короче допустимого.
* [ ] (+) Проверка БД: после регистрации пароль сохранен в виде BCrypt-хеша, а не в открытом виде.

### FR-02: Уникальность email
* [ ] (-) Регистрация с email, который уже есть в системе (ожидаем 401 Unauthorized или 400 Bad Request с понятным сообщением).

### FR-04: JWT-токен
* [ ] (+) Логин с верными данными возвращает 200 OK и валидный JWT-токен в теле ответа.
* [ ] (-) Логин с неверным паролем (ожидаем 401).
* [ ] (-) Логин с несуществующим email (ожидаем 401).
* [ ] (+) Запрос к защищенному эндпоинту с валидным токеном проходит успешно.
* [ ] (-) Запрос к защищенному эндпоинту без токена (ожидаем 401).
* [ ] (-) Запрос с истекшим или поддельным токеном (ожидаем 401).

### FR-05: Роли и разграничение доступа
* [ ] (+) Обычный пользователь (User) имеет доступ к своим снам и профилю.
* [ ] (-) Обычный пользователь не имеет доступа к админским эндпоинтам `/api/admin/*` (ожидаем 403 Forbidden).
* [ ] (+) Администратор (Admin) имеет доступ к админским эндпоинтам.

## 2. Модуль «Управление снами» (FR-06 — FR-08, FR-15)

### FR-06: Создание сна
* [ ] (+) Создание сна с валидными данными (заголовок, текст, дата).
* [ ] (-) Создание сна с пустым заголовком или текстом (ожидаем 400).
* [ ] (-) Создание сна с датой в будущем.

### FR-07: Изоляция данных (чтение)
* [ ] (+) Пользователь получает список только своих снов.
* [ ] (+) Пользователь получает свой сон по ID.
* [ ] (-) **IDOR**: Пользователь А пытается получить сон Пользователя Б по ID (ожидаем 403 Forbidden или 404 Not Found).

### FR-08: Редактирование и удаление
* [ ] (+) Пользователь редактирует свой сон (изменения сохраняются).
* [ ] (-) Пользователь пытается отредактировать чужой сон (ожидаем 403/404).
* [ ] (+) Пользователь удаляет свой сон (сон исчезает из БД).
* [ ] (-) Пользователь пытается удалить чужой сон (ожидаем 403/404).

### FR-15: Поиск по снам
* [ ] (+) Поиск по точному совпадению в заголовке.
* [ ] (+) Поиск по тексту сна (регистронезависимый).
* [ ] (-) Поиск по несуществующему слову возвращает пустой список, а не ошибку.

## 3. Модуль «AI и Анализ снов» (FR-09 — FR-13, FR-22)

### FR-09: Стратегия «Словарь символов»
* [ ] (+) Анализ текста с известными символами (например, "кошка") возвращает список найденных символов.
* [ ] (-) Анализ текста без известных символов возвращает пустой список, но не падает.

### FR-10 — FR-13: AI-стратегии (Фрейд, Юнг, КПТ, Сонник)
* [ ] (+) Анализ «Фрейд» возвращает текст интерпретации и настроение.
* [ ] (+) Анализ «Юнг» возвращает текст интерпретации.
* [ ] (+) Анализ «КПТ» возвращает текст интерпретации.
* [ ] (+) Анализ «Сонник» (с параметром конкретного сонника) возвращает текст.
* [ ] (-) Запрос несуществующей стратегии (например, `?strategyType=unknown`) возвращает 400 Bad Request.
* [ ] (-) Обработка таймаута AI (проверка ISSUE-001): при недоступности AI возвращается корректная ошибка.

### FR-22: История анализов
* [ ] (+) После первого анализа в БД создается запись анализа.
* [ ] (+) При повторном анализе (другой стратегией) обновляется существующая запись (согласно диаграмме состояний сущности Dream), а не создается дубликат.

## 4. Модуль «Статистика» (FR-14)

### FR-14: Сбор и отображение статистики
* [ ] (+) Запрос статистики для пользователя с несколькими снами возвращает верные данные (TotalDreams, AverageDreamLength).
* [ ] (+) Запрос статистики возвращает топ-символы (PopularSymbols) и распределение настроений (MoodDistribution).
* [ ] (-) Запрос статистики для пользователя без снов возвращает нулевые значения и пустые массивы.

## 5. Модуль «Админ-панель» (FR-16 — FR-18)

### FR-16, FR-17: Просмотр данных
* [ ] (+) Админ получает список всех пользователей системы.
* [ ] (+) Админ получает список всех снов всех пользователей.

### FR-18: Удаление данных
* [ ] (+) Админ удаляет любого пользователя.
* [ ] (+) Админ удаляет любой сон.

## 6. Инфраструктура API и безопасность (FR-19 — FR-21, NFR)

### FR-19: Формат ответов
* [ ] (+) Все успешные ответы API обернуты в единый формат `ApiResponse<T>` (содержат поля `Success`, `Data`).

### FR-20: Обработка ошибок
* [ ] (+) Негативные тесты возвращают структурированную ошибку (JSON), а не HTML-страницу с трейсом (проверка работы `ExceptionHandlingMiddleware`).
* [ ] (-) В сообщениях об ошибках не раскрываются пути к файлам, SQL-запросы и стек вызовов (базовая проверка безопасности).

### FR-21: Swagger-документация
* [ ] (+) По адресу `/swagger` открывается UI, и в нем присутствуют все контроллеры и эндпоинты.
